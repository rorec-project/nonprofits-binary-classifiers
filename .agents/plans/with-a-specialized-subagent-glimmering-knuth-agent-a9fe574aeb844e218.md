# Literature-Currency Audit — Weak Supervision / LLM Annotation Methods

- **Date:** 2026-06-10
- **Mode:** read-only audit (no source files modified; findings written only to this plan file)
- **Scope:** `src/binary_classifier/annotate/*`, `src/binary_classifier/qc/{agreement,evidence}.py`, and the project's own June-5/6 literature/tech notes.
- **Two baselines for "currency":** (1) does the *code* implement what current best practice — and the project's own 4-day-old notes — recommend? (2) is anything newer than even those notes captured? The code repeatedly lags its own notes; that is where most findings sit.

---

## (a) Implemented approach (with file:line)

**LLM-as-primary weak supervision (single-item classification, not pairwise judging).**
- Provider-agnostic `Annotator.annotate(text, ein2)` returns a `LabelRecord`; `annotators/base.py:56-68`. Temperature fixed at 0.0, `seed=42`, exponential backoff (`base.py:34-52,76-78`).
- Two live providers: OpenAI (`annotators/openai_annotator.py:65-117`, structured `json_schema` strict output, captures `system_fingerprint` at `:109`) and a local open-weight vLLM arm (`annotators/vllm_annotator.py:67-104`, `guided_json`; note: vLLM path does **not** capture a fingerprint). Routing in `annotators/factory.py:51-73`.
- **Model × prompt ensemble.** Full matrix built in `run_annotation.py:186-193` over confirmed production specs × prompts `v1/v2/v3` (`run_annotation.py:108`). Bake-off scores the candidate × prompt matrix on the coded `prompt_dev` split and proposes an **unconfirmed** slate (`bakeoff_prompts.py:98-151`); promotion to `production_slate.json` is a human gate G2 (`run_annotation.py:51-84`). Resume keyed by `(EIN2, source_id=f"{model_id}__{prompt_id}")` (`run_annotation.py:199-206`, `schema.py:338-359`).
- **Structured JSON output with confidence + evidence spans.** Schema fields `binary_label ∈ {religious, nonreligious, ambiguous_review, insufficient_information}`, `confidence`, `domains_present`, `evidence_spans`, `boundary_notes`, `reason` (`schema.py:45-89`). Abstain classes → `label = NaN` (`schema.py:166-180`). Raw response + provenance (model/prompt/temp/seed/timestamp/fingerprint) persisted in the long/tidy store (`schema.py:189-216, 279-297`).

**Aggregation — majority vote default; DS/CROWDLAB present but quarantined.**
- `majority_vote` (`aggregate.py:21-81`): per-EIN2 plurality, ties → abstain (`:60-61`), all-abstain → human review (`:39-52`). **Confidence is reported but never used to weight the vote** — `silver_confidence` is just the mean confidence of the winning votes (`:64-67`).
- `aggregate_dawid_skene` via crowd-kit (`aggregate.py:87-122`) and `aggregate_crowdlab` (`aggregate.py:125-149`, an explicit **stub** — needs classifier `pred_probs` that are not wired). Dispatcher defaults to `"majority"` (`aggregate.py:155-176`); QC calls it with `method="majority"` (`agreement.py:99`). Nothing probabilistic / soft-label is wired into training.

**Confidence & hallucination control — evidence-span verification.**
- `verify_evidence_spans` checks each span is a **verbatim substring** of source text: `if span in source_text` (`evidence.py:75-81`). Exact, case/whitespace/unicode-sensitive, blind to paraphrase.
- `abstain_fabricated_positives` downgrades religious-positive records carrying a fabricated span to abstain (`evidence.py:94-127`), gated by `cfg.qc.abstain_on_fabricated_positive` in the stage-04 script (`scripts/04_quality_check.py:88-94`).

**Agreement gate — one-shot freeze at ≥0.85.**
- `run_quality_check` computes a full bundle — confusion matrix, minority-class P/R/F1, MCC, balanced accuracy, **Cohen's κ**, PR-AUC, and bootstrap 95% CIs for accuracy and minority-F1 (`agreement.py:200-301`).
- **But the blocking gate uses raw percent agreement only:** `agreement = agree/len(valid)` then `if agreement < threshold: raise` (`agreement.py:124-126, 162-174`). Threshold `0.85` (`config/religious_missions.yaml:63`, `config.py:215`). The richer metrics and the CI it just computed are logged but do **not** gate. Pass → freeze silver labels (`agreement.py:176-179`). The module docstring even warns κ is prevalence-sensitive and "should not be a standalone gate" (`agreement.py:9-13`) — yet raw agreement, which is *more* prevalence-sensitive, is the sole gate.

**Drift / canary set — designed but synthetic.**
- `CANARY_EIN2` is 5 synthetic placeholders, self-flagged "replace with real canary EIN2s" (`run_annotation.py:35-41`); `canary_only` filter exists (`run_annotation.py:195-197`). `system_fingerprint`, `seed`, `temperature`, `run_timestamp` are captured per record (`schema.py:110-156`) but **nothing consumes them** for drift detection — no fingerprint diff, no canary re-run comparison, no change test.

## (c) Ranked, concrete updates worth considering

1. **Make the freeze gate chance-corrected and CI-aware (highest impact, lowest cost).** Gate on Cohen's κ (or Krippendorff's α) and/or the **bootstrap CI lower bound** of minority-F1/balanced accuracy — all already computed in `agreement.py`. Keep raw agreement as a reported diagnostic, not the gate. Directly supported by SILICON and the Variance-Aware protocol; closes the internal inconsistency where the code computes good metrics then ignores them. (DRIFTED #4)

2. **Use confidence/disagreement in aggregation, not just reporting.** Add a confidence-weighted vote and/or route high-inter-prompt-disagreement EIN2s to human review (the disagreement signal is already in the store). Optionally wire the Snorkel `LabelModel` arm the notes call for and train end-models on soft labels. (GAP #2c/#2d)

3. **Harden evidence verification + calibrate confidence.** Replace exact `span in source_text` with normalized matching (case/whitespace/unicode fold) at minimum, and consider an NLI/attribution faithfulness check; treat raw LLM `confidence` as uncalibrated — calibrate (e.g., isotonic/Platt on the gold set) before using it in PR-AUC or as a selection/abstention signal, ideally via a conformal/selective-abstention rule. (DRIFTED/GAP #3)

4. **Operationalize drift monitoring.** Replace synthetic `CANARY_EIN2` with a real, **hashed/versioned** frozen canary subset; pin exact model snapshots; on any model-ID/fingerprint change, re-run the canary and compute κ/α vs the frozen baseline with a documented change threshold. The plumbing (fingerprint, seed, temp, timestamp) already exists — it just needs a consumer. (GAP #5)

5. **Add a multi-config robustness check before trusting silver labels (defensive).** Given "LLM Hacking" (Baumann et al. 2025), report label stability across the prompt variants and ≥2 model families already in the matrix, and flag where downstream prevalence/conclusions flip — the pipeline runs the matrix but doesn't summarize cross-config stability as a guardrail.

6. **Add a demographic/identity-bias audit (domain-specific risk).** Törnberg 2026 shows LLM annotators reproduce racial/dialect stereotypes; religious-mission text correlates with denomination/ethnicity, so audit agreement/error by likely-identity strata, not just overall.

## Unresolved points worth asking the human

- **Gate policy:** Move the freeze gate to chance-corrected κ/α and/or a CI lower bound? If so, what threshold and on which metric (κ vs α vs minority-F1 CI floor)? Raw 0.85 under minority-class prevalence may pass on a near-baseline classifier.
- **Are DS/CROWDLAB meant to stay quarantined permanently,** or revisited once a baseline classifier produces `pred_probs` (which would unblock CROWDLAB)? Current quarantine is defensible *now*.
- **Calibration vs raw confidence:** is downstream use of LLM `confidence` (PR-AUC, weighting, abstention) intended to assume calibration? If yes, a calibration step is needed; if confidence is only diagnostic, document that it must not gate.
- **Canary scope:** which real EIN2s should seed the frozen canary, and what κ/α drop should trigger a re-label/escalation?
- **Out of scope confirmation:** this audit covers weak-supervision/annotation only. Downstream-inference corrections (DSL/PPI), which the notes flag for when classifier outputs become regression variables, are a *separate* currency question — confirm whether that belongs in a follow-up.
